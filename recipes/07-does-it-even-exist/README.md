# 07 它到底存不存在

對應 [Day 7](https://ithelp.ithome.com.tw/users/20138924/ironman/9086)。

```bash
bash check-pkgs.sh express zod   # 把 AI 給你的套件名餵進去，逐一到 npm 註冊處查
pbpaste | bash check-pkgs.sh -   # 從剪貼簿吃，一行一個
bash verify.sh                   # 全部
bash verify.sh 1                 # 只跑「分得出沒有跟沒問到」那節
bash verify.sh 4                 # 只跑「差一個 ^ 就換答案」那節
bash mutations.sh                # 反過來：把腳本弄壞，看上面那支會不會抓到
```

**跑之前先讀 `check-pkgs.sh`。** 這個系列的規矩是不要跑你沒讀過的東西，而這一份剛好是「該不該信這包程式碼」本身。`check-pkgs.sh` 兩百三十幾行，只用 `curl` 打 `registry.npmjs.org` 跟 `api.npmjs.org` 的唯讀 API，不裝東西、不碰 `npm`：把 `npm_config_cache` 指到一個空目錄再跑，實測寫 0 個檔（2026-08-07）。

**會在你機器上留東西的是第 4 節與第 5 節**，兩節都因為呼叫 `npm` 而寫 `~/.npm`，而那個目錄跑完不會清。2026-08-07 實測，把 `npm_config_cache` 指到一個全新空目錄各跑一次：

| 跑什麼 | 下載到哪 | 寫進 npm 快取 |
|---|---|---|
| 第 1 到 3 節（只有 `check-pkgs.sh`） | 沒有 | 0 個檔 |
| 第 4 節的 `lockfile-demo.sh` | 沒有套件本體 | 184 個檔約 5.6 MB（`_cacache` 的註冊處中繼資料，另有 4 個 `_logs` debug log） |
| 第 5 節的 `npm ci --ignore-scripts` | `mktemp -d` 裡 67 個套件約 3.9 MB，跑完刪掉 | 284 個檔約 5.8 MB（`_cacache` 佔 270 個約 5.7 MB，另有 6 個 `_logs` debug log 與 7 個簽章驗證用的 `_tuf`） |

`--package-lock-only` 擋掉的是套件本體，不是連線：`npm` 還是要跟註冊處要每一個相依的中繼資料才解得出版本，那些回應會落進 `~/.npm/_cacache`。計量網路或不准對外寫入的機器上，跑 `bash verify.sh 4` 跟 `bash verify.sh 5` 之前先知道這件事；要留乾淨的話 `npm_config_cache=$(mktemp -d) bash verify.sh`，跑完自己刪。

第 5 節每一個會真的裝東西的指令都帶 `--ignore-scripts`。不帶的話 `npm` 會用你的身分去跑相依自帶的 `preinstall` 與 `postinstall`，2025 年 PhantomRaven 走的就是這條路，而這一份從頭到尾在教的就是「別在還沒確認之前把執行權交出去」。旗標擋掉的只有那些腳本：套件本體照樣下載、`~/.npm` 照樣寫，上面那張表就是帶著旗標量出來的。這件事不靠你記得在前面多打一段環境變數，腳本自己帶。

同一節有一輪故意不帶旗標，那是正向對照。那一輪裝的是一顆自製的本地探針套件，它的 `preinstall` 只做一件事：往 `LIFECYCLE_MARK` 指的絕對路徑寫一個檔。對照那輪要先看到檔出現，帶旗標那輪的「檔不在」才算數。少了對照的話，探針從頭到尾都不會寫檔的時候那條斷言照樣是綠的，而「腳本沒跑」跟「腳本跑了但沒留下痕跡」在畫面上是同一件事。

需要 `bash`、`curl`、`node`，第 4 節與第 5 節另外需要 `npm`。`npm 9`（Node 18 那條線的出廠版）上第 4 節照跑，但第 5 節的 `npm audit signatures` 會整片報「public key has expired 2025-01-29」：過期的是那支 npm 內建的註冊處公鑰，不是套件有問題，所以那一條算這台不適用而跳過，不印紅燈（2026-08-07 用 npm 9.9.4 實測）。`sources/fetch.sh` 重抓來源快照時還會用到 `python3`，那支跟 `verify.sh` 無關。沒有那些工具的時候相關的節會跳過，而**跳過會讓離開碼變成 1**。`bash verify.sh && echo 通過` 不該在一台連 `node` 都沒有的機器上印出那句話。

「沒裝」跟「裝了但註冊處沒回應」分開報，因為這一份要教的正是這件事。2026-08-07 在 macOS 上實測（node 24.3.0、npm 11.4.2），工具用 PATH 影子目錄拔掉、斷線用一支一律回非零的 `curl` 替身模擬，`api.npmjs.org` 被擋用一支只擋那台、其餘原樣轉給真 `curl` 的替身模擬。換成 npm 9 的話簽章那條會跳過，「什麼都有」跟「`api.npmjs.org` 被擋或限流」那兩列各少一個綠燈、多一個跳過，其餘四列第 5 節本來就整節跳過，不受影響：

| 情況 | verify.sh 的反應 |
|---|---|
| 什麼都有 | 23 綠 / 0 紅 / 0 跳過，離開碼 0 |
| 沒有 `curl` | 2 綠 / 0 紅 / 6 跳過，離開碼 1。訊息點名 `check-pkgs.sh` 本身跑不起來 |
| 沒有 `node` | 1 綠 / 0 紅 / 7 跳過，離開碼 1 |
| 沒有 `npm` | 15 綠 / 0 紅 / 3 跳過，離開碼 1。前三節照跑 |
| `curl` 在，但問不到註冊處 | 4 綠 / 0 紅 / 6 跳過，離開碼 1 |
| `api.npmjs.org` 被擋或限流 | 不算缺法：名字照樣查得準，下載那一欄印「錯誤」並在收尾出聲。但第 3 節要比的是真的下載數字，沒有數字就跳過，所以是 22 綠 / 0 紅 / 1 跳過，**離開碼 1**，跟上面那句「跳過會讓離開碼變成 1」是同一件事 |

沒有任何一種缺法會印出紅燈：**紅燈的意思是你要驗的東西壞了，不是這台機器不適用。** 反過來說跳過也不算通過，所以它把離開碼推到 1。

四種缺法下都還綠著的只有一條：第 1 節那條把 `PATH` 清空、看 `check-pkgs.sh` 會不會當場停在離開碼 2 的檢查。它不需要網路也不需要任何工具在，所以少了什麼都驗得到。

「把註冊處指到連不到的位址、看它會不會把 `express` 講成不存在」那兩條要再多一點：`curl` 跟 `node` 得在（不然 `check-pkgs.sh` 是死在「工具不在」，驗到的是另一條路），所以只在「沒有 `npm`」跟「問不到註冊處」那兩列還綠著。

打錯節號會直接停：`bash verify.sh 9` 印「沒有第 9 節」、離開碼 2。不擋的話那會是 0 綠 0 紅 0 跳過然後離開碼 0，也就是這一份最想抓的那種假綠燈。

同一個形狀在另外兩支上也擋掉了，離開碼一律是 2：

| 情況 | 行為 |
|---|---|
| `bash mutations.sh 23`（超出範圍） | 印「一種突變都沒跑到。沒有第 23 種，可用的是 1 到 22」。不擋的話是「抓到 0 種 / 漏掉 0 種」然後離開碼 0。數的是「跑了幾種」而不是把結果加起來，不然一種明明跑了、只是這台機器測不到，收尾會回頭說「沒有第 N 種」 |
| `bash mutations.sh abc` | 印「種類編號要是數字，收到的是「abc」。」 |
| `lockfile-demo.sh` 兩邊都跑不出結果 | 印 npm 自己講的錯誤。不擋的話它會照樣印「看兩件事」，而你沒有東西可看 |
| `lockfile-demo.sh` 只跑出一邊 | 一樣印 npm 的錯誤然後停。一邊不成對照，那一行不能單獨拿來下結論 |

`lockfile-demo.sh` 失敗的時候不替你猜原因，它把 npm 的 stderr **前三行**原樣端出來。取前三行是因為 npm 的訊息是原因在前、罐頭建議在後，取後三行拿到的會是「你是不是在代理後面」那種對誰都一樣的話。分不分得開看得出來：

```
註冊處連不到      快取目錄不可寫
npm error code ECONNREFUSED    npm error code ENOTDIR
npm error syscall connect      npm error syscall mkdir
npm error errno ECONNREFUSED   npm error path .../_cacache/tmp
```

## 這裡面有什麼

| 檔案 | 是什麼 |
|---|---|
| `check-pkgs.sh` | 主角。把套件名逐一丟給註冊處，**開頭先跑一組對照**才敢報答案 |
| `lockfile-demo.sh` | 同一個相依差一個 `^`，`npm audit` 給不同答案。不動你的專案，但會寫 npm 快取 |
| `verify.sh` | 五節：對照組（兩台主機）／三種輸入與名字後面的版本號／下載數不是活著的證明／`^` 的差別／`npm ci`、擋掉相依的生命週期腳本與簽章 |
| `mutations.sh` | **故意把腳本弄壞二十二種，看 `verify.sh` 會不會紅。** 有一種沒紅就是假綠燈 |
| `sources/` | 那篇幻覺套件論文（摘要與全文）跟 npm 官方文件的快照，加一張原句對照表，不用相信轉述 |

## 對照組是這一份的地基

`check-pkgs.sh` 每一輪開頭都問兩個名字：一個一定在（`express`），一個一定不在（隨機生的長名字）。兩邊分別答 200 跟 404 才往下走。

因為**「查不到這個套件」有兩種原因**：註冊處說沒有，或者你根本沒問到註冊處（網路斷了、`curl` 沒裝、公司代理擋掉）。這兩種在畫面上長得一模一樣，而它們的結論相反：前者代表這個名字是 AI 掰的，後者代表你什麼都還不知道。

沒問到的時候它印「錯誤」不印「沒有」，而且離開碼是 2。`mutations.sh` 的前三種就在打這裡：把對照組拿掉、把「錯誤」改口成「沒有」、把 404 判成「查到」，三種都要讓 `verify.sh` 紅。

### 下載數那台掛掉：大聲降級，不是停下來

名字查 `registry.npmjs.org`，週下載數查 `api.npmjs.org`，是兩台。後者掛掉的時候，原本那一欄會印「?」然後照樣離開碼 0，那是同一個「問不到長得像沒有」的錯，只是換一欄發生。

但這裡**不停下來**。這篇要回答的是「這個名字存不存在」，那隻靠註冊處那台就夠了；公司代理只放行註冊處的人，硬停會讓他整支不能用，而他本來拿得到最重要的那個答案。而且 `api.npmjs.org` 會限流，把它變成硬相依等於給這支工具加一個天生會抖的依賴。

病灶是靜默不是缺硬停，所以改成大聲降級。那一欄有三種值，其中兩種不是數字，彼此分得開：

| 那一格 | 意思 |
|---|---|
| 數字 | 真的問到了 |
| `錯誤` | 沒問到。**不是**沒人下載 |
| `關` | 你自己用 `NPM_DOWNLOADS=off` 關掉的 |

`錯誤` 跟判定欄的「查到／沒有／錯誤」用同一套兩個字的詞彙。全形字在終端機佔兩個顯示欄位，而 `printf` 的 `%10s` 是按字元數補，補出來「錯誤」那幾列會比數字那幾列短兩欄，整張表就歪了。所以那兩欄的非數字值是直接寫死補幾格，不去算寬度（`check-pkgs.sh` 的 `dlcell` 與 `repocell`）。寫死就會有人改錯，所以 `verify.sh` 有一條去量顯示寬度：每一列的週下載欄右緣要落在第 15 欄、套件欄左緣要落在第 47 欄，對不上就紅。

`錯誤` 底下有三種原因，一個欄位分不了那麼細，所以由表格上方那幾行字跟收尾去講是哪一種：那台整台問不到、那台對不存在的名字也回 200、或者整台好好的只有這一顆問不到。中間那種是這樣來的：下載數那台跟註冊處那台一樣要問兩個名字。只問一個一定在的，一台「對什麼名字都回 200 加一個數字」的自建鏡像或代理就會過關，然後它編的數字會被印進週下載欄，跟真的量到的長得一模一樣，還附贈一條「上週只有 0 次下載」的假警告。官方那台對不存在的名字回 404，所以踩得到這個的是把 `NPM_DOWNLOADS` 指到別處的人。

判準也要跟真的查詢一致：`HTTP 200` 不等於拿得到數字。對照如果只看狀態碼，一台整台回 200 卻塞一頁 HTML 的代理會過關，接著每一顆都印「錯誤」，而收尾會去逐顆點名，把你導向查個別套件，實際壞掉的是整台。

還有一件事比欄位重要：下載數問不到的時候，「上週只有 N 次下載」那條提醒就不會出現。**檢查沒跑跟檢查跑完沒事，畫面上必須長得不一樣**，所以收尾會多一段：

```
── 這一項我沒幫你看 ──
下載數那台問不到，所以「下載數低不低」這條沒跑：
  express nginx-log-parser
那不代表它們的下載數沒問題，是這一項根本沒檢查。
```

「你自己關的」跟「它壞了」訊息不一樣，因為你需要分得出自己是主動放棄還是環境要修。

### 名字後面黏著版本號

AI 給你的那行通常是 `npm install express@4.19.2`，整段複製進來的話名字後面就帶著版本。`check-pkgs.sh` 會把版本切掉查 `express`，但**會印一行告訴你它切了**：

```
express｜你給的是 express@4.19.2，我查的是名字 express 在不在，版本 4.19.2 沒查。
```

不切的話註冊處回 404，這支就會把一個真的存在的套件講成 AI 掰的，那是這一份最不想要的答案。切了不講也不行，那等於把你問的問題換掉。scoped 套件（`@fastify/client-cert`）開頭那個 `@` 不是版本分隔，不會被誤切。

## 下載數不是活著的證明

第 3 節拿 `express-rate-limiter` 當例子：最後一版 1.3.1 發於 **2015 年 11 月**，上週仍有一千多次下載（2026-08-07 實測 1863 次）。

這裡不主張那個套件有惡意，只主張一件事：**下載數證明不了有人在維護它。** `check-pkgs.sh` 印的停更年數、版本數、有沒有填原始碼位置，同理都不是安全判定，是「這幾條沒有人在幫你看，你自己去看一眼」的理由。

### 「最後發布」不能讀 `time.modified`

同一個套件，註冊處的 `time.modified` 是 **2022-06**，`time["1.3.1"]` 是 **2015-11**，差了將近七年，而且方向是讓它看起來比實際新。`modified` 是中繼資料被動過的時間，改個 dist-tag、改個 README 都會往前跳。

`check-pkgs.sh` 因此取 `time[dist-tags.latest]`。這一條值得單獨拿出來講，是因為它跟這一份的主題同形：**你以為在讀「還有沒有人在維護」，其實讀到的是另一個欄位。** 拿 `modified` 當判準的話，一個十年沒發版的套件在「停更超過兩年」那條警告下不會亮。

## `npm audit` 掃的是 lockfile，不是你的意圖

第 4 節兩邊都宣告 `express` 4.19.2，只差一個 `^`。2026-08-07 實測：浮動的 `^4.19.2` 是 0 則弱點，釘死的 `4.19.2` 是 7 則。

**不要讀成釘版本比較危險。** audit 報的是「你鎖住的那份 lockfile 現在對得上幾則公告」，浮動那邊的 0 是今天的 0，明天同一份 `package.json` 解出來的可能就不是。

同一節還印一個數字：宣告 1 個相依，lockfile 裡有 68 個套件（同日實測）。那 67 個你沒選過，而它們跟你選的那個裝進同一個 `node_modules`。

## 邊界

這裡管的是「裝進來之前信不信它」，判準只到「這個名字在不在註冊處、有沒有人在看」。**名字查得到不等於那包程式碼安全**，真的有人搶註冊一個像樣的名字再塞東西進去，這支腳本會回報「查到」。它擋的是 AI 憑空生名字那一類，那類佔多數，但不是全部。

「執行的時候把它關在哪裡」是另一件事，[Day 6](../06-run-it-somewhere-else/) 那份處理。這一份在第 5 節用 `--ignore-scripts` 擋掉相依的生命週期腳本，護的是跑這份 recipe 的你；你查完之後真的把那包東西裝進專案的時候，那個旗標不會跟著過去。

`npm audit signatures` 通過也只代表你下載到的檔案跟註冊處那份對得上，**不代表發布者可信**。原句在 `sources/npm-audit-signatures.txt`。
