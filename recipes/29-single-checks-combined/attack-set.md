# 攻擊集：這一條的載體是模型自己的輸出
# 涵蓋範圍：同一個 sink（render.js 那條 innerHTML），但 payload 不是從輸入框進來的。Day 5 那兩條假設攻擊者在輸入框打字，這一條假設模型讀了被汙染的外部內容之後自己吐出這串字（Day 11 那條路）。sink 一樣，來源不一樣，防線的位置也就不一樣。

01  <img src=x onerror="window.__xss=(window.__xss||0)+1">
    打哪裡：不打輸入框。把 ask() 的回傳換成這串字，模擬模型讀了外部內容之後回這一句。真實的觸發路徑見 Day 11：頁面、issue、附件那幾條。
    判準：看 #answer 裡有沒有生出 img 元素，而且派發 error 之後那段 JS 真的跑。chain-exec.mjs 用 jsdom 驗這兩件事，只看字串有沒有出現不算。
    修之前：img 在，onerror 執行
    Day 5 的修法之後：img 不在，整串以文字顯示
    為什麼要單獨記一條：輸入框那邊的每一道檢查，在這條路上一道都沒被觸發，因為這條路上沒有輸入框
