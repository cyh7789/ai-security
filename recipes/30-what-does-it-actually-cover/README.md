# 這些案例現在走不走得通

前二十九天各自留下了一份東西：攻擊集、應放行集、回歸案例、掃描的核對紀錄、成分表。
每一份自己都對，但是沒有人回答得出「所以這個專案現在防到什麼程度」。

這份 recipe 就是回答那句話用的，而它給的答案有三欄：**過了、沒過、沒測**。

## 怎麼跑

```bash
bash verify.sh          # 這份自己的檢查
bash rollup.sh          # 重跑各組來源，算一次，跟簽核比
bash rollup.sh --list   # 只印判準，一發都不跑
```

要 `node` 與 `jsdom`（在儲存庫根目錄跑 `npm install`），因為其中一組要重跑第 29 天那條鏈。
另外它會去跑第 24 天的 `run.sh` 與第 14 天的 `verify.sh`，所以整支要十幾秒。

## 兩份人填的判準檔

| 檔 | 管什麼 |
|---|---|
| `standard.tsv` | 哪些東西進這張表、每一組的重跑指令、簽核過的當前狀態 |
| `uncovered.tsv` | 哪些東西**不**進這張表，一列一個理由 |

`rollup.sh` 只做兩件事：把那幾條重跑指令跑一次，然後跟簽核欄比。
它不決定任何一列該算哪一欄。判準不能從被評的那個東西的輸出反推，得先由人寫下來（第 25 天那條紅線）。

## 一列要長什麼樣

分兩層。混成一套條件的話，判準自己就會跟表上的「整條鏈」打架。

**第一層決定進不進表**：有一條講得出來的路徑，跟一個可觀察的終點。那個終點要在沒打進去的時候不會亮。

**第二層決定能不能簽過了或沒過**：還要有一個具體的輸入，跟一條寫得下來的重跑指令。

第一層過了、第二層還不完整，那一列留在表上簽沒測。「整條鏈」就是這種：路徑跟終點說得出來，但還沒有具體輸入，也沒有重跑指令。

第一層都沒過的，連進表都不必。那些東西不是不重要，是它回答的不是「這條路現在走不走得通」。第 26、27 天那兩份核對紀錄就是這種：它們量的是模型指得準不準，跟防線擋不擋得住不是同一件事，混進同一個分母算通過率，兩個數字都會失去意思。

## 簽核不是及格

`standard.tsv` 的簽核欄現在寫著 `9/7/0`，那個 7 是七條已知會被打穿的缺口。
把它們跟通過放同一欄的那一刻，這張表就變成一個每一列都寫著過了的儀表板。

`rollup.sh` 回 1 的條件是**跟簽核對不上**，不是有東西沒過。
包括從沒過變成過了：那也是狀態變了，也要人回去重新看一次再簽。

## 沒有重跑指令的那幾列

`standard.tsv` 的「重跑」欄寫「（沒有）」的列，簽核只能是 `0/0/1`，`verify.sh` 第 3 條守這件事。
沒有重跑指令的東西不會有結果，它只會在下次有人問「這個測過了嗎」的時候被答成「應該有吧」。

## 接回 CI

分級表在 `../22-when-should-it-stop-you/levels.tsv`，這一支是 A 級。
`verify.sh` 第 6 條會確認**每一支** recipe 都有分級，一支沒有就沒過，
因為沒有分級等於不在 CI 的任何一個矩陣裡，而那種東西只有作者本機跑過。
