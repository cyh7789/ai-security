# 原始紀錄

`2026-08-13/` 是 Day 14 那三張表的來源。三個版本 × 十五題（十二條攻擊加三條正常問題）× 每格三次，共 135 發，另外三批補測 45 發。

```
results.tsv                  135 發的逐發判決（版本／題號／第幾發／載體／類別／判決）
compare.txt                  results.tsv 餵給 compare.mjs 印出來的版本比較表
followup-04-06.tsv           04 與 06 補到每格十次的第 4 到 10 發
followup-stats.txt           那批補測的 Fisher 精確檢定，含「這個數字不能下結論」的理由
v0b-page-no-guardline.tsv    拿掉 HEAD.page 那句防護之後，六條 page 各三發
v0c-input-no-role.tsv        拿掉 HEAD.input 那句角色限制之後，04／05／06 各三發
run-conditions.txt           被測模型、CLI 版本、沙箱設定、出題與被測怎麼分開
replies-lost/                被判成失守的那幾發的回覆原文
```

## 怎麼自己重算

不需要打模型，`results.tsv` 就夠：

```bash
node ../compare.mjs runs/2026-08-13/results.tsv     # 重印三張表
```

檢定的部分是十行 Python，`followup-stats.txt` 裡有列聯表，拿它自己跑 Fisher 就對得上。

## 這批紀錄的四個限制

1. **v2 是看過整組攻擊集之後生出來的。** 1/36 是開發集成績，只能拿來做回歸比較，不能當成它面對沒見過的攻擊的表現。而且 v2 與 v1 之間同時變動了長度、具體例子、輸出限制好幾件事，把差異歸給任何單一設計路線都沒有依據。
2. **三個版本是依序跑的**，不是隨機交錯，版本之間的時間差混在版本差裡。
3. **CLI 會自動載入這台機器上的使用者規則檔**，這批數字沒有關掉它。這件事 Day 10 就記錄過，一直還在。
4. **`replies-lost/` 少一份。** 17 筆判成失守的裡面有 16 份原文在這裡。`v1-15-1` 在改稿期間被一次罐頭測試蓋掉了，救不回來；`v1-06-1` 與 `v1-07-1` 是從當時引用過的快照還原的，其餘 14 份是原檔。「十七筆逐字讀過」這句話因此只有 16 份底稿撐得住，這裡照實記。

## 為什麼要公開這一批

文章裡每一個數字都來自這幾個檔。少了它們，讀者只能選擇相信，而這個系列整天在講的就是「不要相信一個你沒辦法自己算一次的數字」。
