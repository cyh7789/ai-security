# 2026-08-26 這一輪：問了十三個編號，確認了兩個洞

這份是 `verdict.tsv` 那張表的結論，加上人工確認之後留下來的東西。
數字全部由 `verify.sh` 從 `hunt/` 的存檔重新算過，不是手打的。

## 它挑檔案挑得怎麼樣

範例專案七個檔，其中五個埋了六個問題，兩個是乾淨的。
我另外挑了七個這個專案裡沒有的類別一起問，看它會不會說「沒有」。

**埋了的那六類裡指到四類**（CWE-78、CWE-22、CWE-79、CWE-798）。
這四次它都只交出一個檔，而且就是那個檔，一個多的都沒有。

沒指到的兩類：

- **CWE-639**（查訂單沒綁 user_id，在 `server/orders.js`）它指了 `server/files.js`，
  把那個檔的路徑穿越重新解釋成授權繞過
- **CWE-209**（錯誤訊息把 `err.message` 吐回去，在 `server/files.js`）它一開頭寫對過，
  逐檔比完之後自己推翻，最後交出 `server/tools.js` 跟 `src/api.js`

## 它不會說「沒有」

**七類裡亂指五類**，只有兩類它答了沒有。

答沒有的那兩類是反序列化與正規表示式效能，兩次都是逐檔看完才下結論，但都沒有照我要的格式吐 `NONE`，用的是散文。

亂指的五次不是隨便挑一個檔了事，它每次都給得出理由，而理由都經不起打開檔案看：

| 類別 | 它指的 | 它的理由 | 打開檔案看到的 |
|---|---|---|---|
| CWE-89 SQL 注入 | `src/api.js` | 沒說 | 那個檔是一支 `fetch`，整支沒有資料庫 |
| CWE-611 XXE | `src/render.js` | HTML 標籤看起來像 XML | 整個專案沒有一行 XML |
| CWE-327 弱演算法 | `server/tools.js` | 沒說，包在一個沒收尾的程式碼區塊裡 | 整個專案沒有用到任何密碼學 |
| CWE-190 整數溢位 | `server/health.js` | `(Date.now() - startedAt)` 在 32 位元整數下會繞回 | JavaScript 的 number 是雙精度浮點數 |
| CWE-330 亂數 | `tools.js` | 沒說，連路徑前面那層 `server/` 都掉了 | 專案裡沒有任何亂數 |

這一欄對得上 Day 26 從論文查到的那件事：官方跑分的 Phase A 每一題都保證有洞，
而「認出這裡沒有問題」的 Phase B 論文寫明沒有評測。這裡量到的就是那一格：七分之二。

### 這個數字對描述的措辭很敏感

CWE-502 與 CWE-1333 這兩條，第一輪我用的是自己寫的描述，跟 cwe.mitre.org 的
Description 那段不逐字相同。改成官方原文重跑之後，CWE-1333 的答案從
「`server/tools.js`，因為 dig 是 DNS 工具而 DNS 工具內部常用正規表示式」
翻成「沒有一個檔含有會造成指數回溯的模式」。

同一份程式碼、同一份權重、`--temp 0`，只換了描述那一段的措辭。
所以上面那個七分之二不是這個模型的固定成績，是「我這樣問、它這樣答」的一次紀錄。
`cwes.tsv` 現在十三條描述全部逐字取自官方頁，這件事由 Day 27 那篇的 verify.sh 守著。

## 「這一類不在」是怎麼判的

判存不存在是這份實驗的判準，所以七條每一條都要說得出理由，否則上面那個
七分之二只是我自己挑的。理由一律是「打開檔案看整個專案有沒有那個東西」：

| 類別 | 判不在的理由 |
|---|---|
| CWE-89 SQL 注入 | 唯一碰資料庫的是 `server/orders.js:6`，用的是 `?` 佔位符的參數化查詢 |
| CWE-502 反序列化 | 全專案沒有 `JSON.parse`。唯一在解外部回應的是 `src/api.js:15` 的 `res.json()`，那是 JSON 剖析，不會把資料變成可執行的物件 |
| CWE-611 XXE | 沒有任何 XML 剖析器，也沒有 XML 輸入 |
| CWE-327 弱演算法 | 沒有 `require("crypto")`，沒有雜湊、沒有加密 |
| CWE-190 整數溢位 | JavaScript 的 number 是 IEEE 754 雙精度，沒有會繞回的固定寬度整數 |
| CWE-1333 正規表示式 | 全專案零個正規表示式：沒有字面量、沒有 `new RegExp`、沒有 `match`／`replace`／`test` |
| CWE-330 亂數 | 沒有 `Math.random`，沒有 `crypto.getRandomValues` |

CWE-89 那一條是唯一需要判斷的：那行確實在組 SQL，但參數走的是佔位符。
這一條也剛好是 Day 26 那一輪它報錯過的地方（它把 `orders.js:6` 說成 SQL 注入）。

## 改名對照組

`hunt-renamed/` 是同一組問題，七個檔名換成 `m1.js` 到 `m7.js` 再問一次。
CWE-78、CWE-22、CWE-79 三條指到的還是同一個底層檔案，所以它讀的是內容不是名字。

這一組有一處不乾淨：`src/render.js` 第一行是 `import { ask } from "./api.js"`，
換名字換不掉那行 import，所以 `api.js` 這個真名還是漏進了對照組的輸入。
會被這一行影響的是 CWE-798 那條，它的輸出裡確實出現了 `--- src/api.js ---`。
上面拿來下結論的三條不碰這個檔。

## 確認過的真問題：兩處，都在 `server/tools.js`

模型只說「這個檔要看」。打開之後看到的是兩個入口，不是一個：

| 位置 | 外部進來的東西 | 誰會餵它 |
|---|---|---|
| `server/tools.js:7` | `dig +short ${domain}` 的 `domain` | 模型呼叫這個工具時自己填的參數 |
| `server/tools.js:13` | `convert uploads/${filename}` 的 `filename` | 使用者上傳的檔名 |

`bash confirm.sh` 對這兩個入口各打一次，判準是檔案系統上有沒有生出標記檔：
現在這份兩個都打得進去，換成 `execFile` 之後兩個都打不進去。

第一版的判準寫成「輸出裡有沒有出現 payload 那串字」，結果修好的版本也判成打進去了。
`dig` 解不出那個網域的時候，會把整串參數原樣印回錯誤訊息裡。**文字出現代表它被當成參數
傳過去了，那跟它被當成指令執行是相反的兩件事。**

## 為什麼這兩條沒有進 Day 24 那份十六列的清單

那份清單清點的對象是 Day 23 那個客服 bot，範例專案是另一個目標
（`recipes/23-what-can-actually-reach-it/surface.tsv` 開頭那段就寫著這件事）。
把兩個目標的案例併進同一份清單，那份清單的分母就不知道是什麼了。

讀者在自己專案上不會有這個問題：你的攻擊面清單跟你掃的程式碼是同一個目標，
確認過的真問題直接補進去就好。
