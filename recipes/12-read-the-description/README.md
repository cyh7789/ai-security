# 12：讀那一欄

對應 [Day 12｜MCP 工具描述不是寫給你看的：我的掃描器說乾淨，它只是沒去看](https://ithelp.ithome.com.tw/articles/10402601)。

Day 8 你列了一張清單：裝了哪些工具、它們碰得到什麼。那張表看的是權限那一欄。
這一份看的是**描述那一欄**：工具自己回報的那段字，你在 UI 上看不到，
而它會進到模型的上下文裡。

## 三支腳本

```bash
node mcp-desc.cjs --stdio -- node demo/three-tools.cjs
```

問一台 MCP server 有哪些工具，描述**原樣印出來，不截斷**。
`--stdio` 起一個本地行程，`--http <網址>` 打遠端那種。

Day 8 的 `mcp-rpc.cjs` 只有 stdio 那一路（它檔頭第一行就寫了）。
遠端的 server 在設定檔裡是一個網址不是一個指令，那支 spawn 不起來。
我自己的設定檔裡有十一筆，去掉重複登記的是八台不重複的 server，其中六台是這種，
所以那六台的描述我一直沒看過。

```bash
node skill-scan.cjs --quiet demo/tree
```

把指示檔（`SKILL.md` 這一類）全部找出來，印出描述欄並統計形狀。

跟 Day 8 那支 `desc-scan.cjs` 的差別只有兩個，但兩個都會改變答案：
**走訪跟著 symlink 走**，以及**跳過了什麼要講出來**。
舊的那支用 `Dirent.isDirectory()` 判斷要不要往下，
而 symlink 指向目錄的時候那個值是 `false`，整棵子樹被無聲跳過。

`demo/tree/` 底下就是一棵這種樹：`here/` 是真目錄，`linked` 是指到 `demo/away/`
的 symlink，兩個檔藏在那後面。Day 8 那支在這棵樹上只看得到一個檔，而且回結束碼 0。

遠端那一路自己起一台來試（另開一個終端機跑 `node demo/three-tools.cjs --http 8912`）：

```bash
node mcp-desc.cjs --http http://127.0.0.1:8912
```

`demo/three-tools.cjs` 是一台自己造的示範 server，三個工具。`add` 只有功能說明，
`search` 整段是命令句而且完全合法，`add_v2` 的命令句要模型去做跟功能無關的事、
還要它不要講。**三個放在一起是為了證明語氣分不出好壞。**

拿它當測試對象，不要拿別人的 server。

## 兩個結束碼的規矩

跟 Day 8 同一套，因為「乾淨」跟「我沒問到」不能混在一起：

| 碼 | 意思 |
|---|---|
| 0 | 問到了 |
| 2 | 沒問到：起不來、逾時、401、路徑讀不到、繞回來了 |

`verify.sh` 有四條專門盯這件事（第 4、5、6、9 條）。
一個只會回 0 的掃描器，它的綠燈不代表乾淨，只代表它沒有話說。

## 統計那一段不是風險指標

`skill-scan.cjs` 會告訴你有幾份描述含命令句。**那個數字不判斷好壞。**
它量的是這個欄位的正常長相，而正常長相就是命令句。

我自己那批的數字：92 個 markdown、55 份有描述欄，其中 49 份含命令句。
所以「這句聽起來像指令」不能當判準，那是基線不是訊號。
要分的是收件人跟意圖，那一步機器做不了。

## 跑驗證

```bash
bash verify.sh
```

第 8 條會跟 Day 8 那支並排跑同一棵樹，兩支的答案不一樣。
找不到 `../08-what-can-it-touch/` 的話那條會跳過。
