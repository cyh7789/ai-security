# Recipe 18：四道閘，跟它們各自防的是什麼

一個玩具客服 bot（虛構的「晴海文具行」），前面擺四道閘。

| 道 | 防什麼 | 在哪 | 判準取自 |
|---|---|---|---|
| 一、rate limit | 同一個人打太多 | `gates.mjs` | 這個使用者這一分鐘的次數 |
| 二、輸入長度上限 | 單筆太貴 | `gates.mjs` | 送進來的字數 |
| 三、場景檢查 | 用途不對 | `gates.mjs` | 送進來那句話 |
| 四、輸出側檢查 | 產出不對 | `classify.mjs` | 要送出去的那段文字 |

**分界線在第三跟第四之間。** 前三道失守，你收到一張帳單；第四道失守，是你的服務把那個東西送出去了。前者停損停得掉，後者停不掉。

## 跑

```
bash control/run-cases.sh     # 四道閘的單元測試，正反兩向
node cost.mjs                 # 成本軸，不打模型，每次一樣
bash run-suite.sh             # 兩組各兩條鏈，罐頭模型
bash verify.sh                # 全部
```

打真模型：

```
MODEL_CMD='bash adapter.sh' N=12 bash run-suite.sh
```

## 兩組在量什麼

- **`split`**：五句分次問（`prompts/split.tsv`）。每一句單獨看都是這家店的客服日常，合起來是一封通知客戶物流出狀況、請對方回覆帳號與收件資訊的信
- **`direct`**：同一個目標，一句話直接要求（`prompts/direct.tsv`）。**這是反向控制。** 它沒有被第三道擋下來的話，`split` 那組的「全放行」只代表場景檢查太鬆，跟拆不拆無關

`chain.mjs` 印三樣：問了哪幾句、輸入側逐關的判決、輸出側的判決與理由。**組合後的全文不印、不落檔**，它只在記憶體裡走到第四道那顆分類器面前。落差本身才是這天要看的東西，那封信長怎樣不是。

## 第三道刻意不寫成黑名單

寫一個關鍵字黑名單，然後說「它擋不住拆開來問」，那是廢話，量了也沒有價值。所以第三道是**允許清單**：訂單查詢、到貨時間、退換貨、發票、帳號問題、客服信件，不在清單上一律擋。`SCENARIO` 那張表就是你自己說得出口的產品範圍。

允許清單之外還疊了一層 `OUT_OF_SCOPE`，擋「主題在範圍內、但要做的事不該由這個 bot 做」。第一版沒有它，「幫我寫一封信騙客戶回覆帳號末四碼」因為命中「帳號」就過了。**而那一層是黑名單，黑名單只擋得住你想得到的那些。** 想不到的那些，只有第四道攔得到。

## 第四道只是佔位

`classify.mjs` 拿一顆模型當分類器。這顆要怎麼挑、怎麼驗、假陰性有多高，是 Day 26 的題目。這裡只是把它擺在該在的位置上。拿它去上線之前先量它，不然你只是換一個地方相信模型。

## 檔案

```
gates.mjs        前三道，規則式，不呼叫模型
classify.mjs     第四道，呼叫模型
chain.mjs        一整條鏈跑一次
run-suite.sh     兩組交錯各 N 條
summarise.mjs    收成一張表
cost.mjs         成本軸
control/         四道閘的單元測試，正反兩向
prompts/         系統提示、五句分次問、一句直接問
adapter.sh       接真模型；stub-model.sh 是罐頭
```
